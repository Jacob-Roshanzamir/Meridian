# Meridian: handoff brief

Meridian is a head-to-head knowledge race with a sci-fi cockpit look. This folder holds a working prototype (plain HTML/CSS/JS, no build step) that was built as a claude.ai artifact. The job now is to turn it into a **public web game** that anyone can open from a link, starting with students at Loughborough University and growing from there.

The owner is a business management student, not a developer. Explain choices in plain English, keep running costs near zero at first, and prefer simple, well-known services.

## The game as it stands (keep these rules)

- One planet sits on a track between two players. Both get **the same question** at the same time.
- **First correct answer pulls the planet one step** toward that player. A **wrong answer locks you out** of that question. If nobody gets it, nothing moves.
- Win by pulling the planet **5 steps** to your side. After **15 questions**, whoever has it on their side wins; level is a draw.
- Time limit: 25 seconds per question (35 for word grids).
- Question types, mixed roughly 65% trivia / 12% maths / 12% word grid / 11% map:
  - **Trivia** (`questions.js`): 296 questions in 8 categories (science, geography, music, film, literature, space, computing, history), each tagged tier 1–3. Some can appear as typed answers with typo tolerance and listed alternatives.
  - **Maths**: generated by tier in `logic.js` (`mathQ`). Verified: 15,000 generated questions all had the correct answer.
  - **Word grid**: a themed hidden word (`gridQ`). The generator guarantees the answer appears exactly once and no other word from the theme appears.
  - **Map**: tap the named country in a regional map (`mapQ`, `makeProj`, `mapHit`). Currently loads amCharts `worldLow` geodata from jsDelivr. **Replace this with Natural Earth data (public domain)** before any commercial use, as amCharts geodata is freeware with licence conditions.
- **No repeats**: the game remembers seen trivia questions per player and avoids them (`chooseSpec`, `specKey`).
- **Rating**: hidden Elo, shown as 0–100 to one decimal place via a logistic curve (`toDisp`, `fromDisp`). New players start at 30.0. Difficulty (Easy/Standard/Hard) multiplies gains (×0.75 / ×1 / ×1.25) and losses (×1 / ×1 / ×0.8). Note: Hard pays out more than it takes, so ratings drift upward; fix this properly on the server (for example, rate against question difficulty).
- **Bots**: five levels (Cadet 20.0 → Admiral 88.0), with accuracy and answer speed per level (`BOTS`, `botPlan`).
- **Daily Sortie**: one fixed match per day, the same for everyone, with a shareable emoji grid.
- **Drinking game**: 2–8 players pass one phone. Right = +1 point, wrong = 2 sips, typed right = everyone else 1 sip, a wildcard every 5 turns. 18+ confirmation screen, sips only, water reminders, link to drinkaware.co.uk. Keep these safeguards. Not rated.
- **Chess was removed** because the board rendering and puzzle quality weren't good enough. If it returns, use real piece images and puzzles from real games (for example, the Lichess puzzle database, which is CC0).

## Files

- `index.html`, `style.css`: page shell and cockpit styling.
- `app.js`: all screens. Solo vs bot, daily, live multiplayer, drinking game, help and tutorial.
- `logic.js`: pure game logic with no DOM, testable in Node.
- `questions.js`: the trivia bank. Format: `[tier, question, answer, wrong, wrong, wrong, fact, typedAlternatives?]`.

## What the prototype can't do (the reason for this move)

- Live multiplayer currently uses the claude.ai artifact `room` capability (`claude.use("room")`), so both players need Claude accounts. **Replace it with a real-time server** that anyone can use (for example, WebSockets on a small Node server, or a hosted realtime service).
- Ratings, seen questions and daily results live in `localStorage`. **Move them to a database with accounts** so they follow the player across devices.
- The host's phone currently decides who answered first. **Make the server the referee**: it sends the question, timestamps answers on arrival, and decides the winner. This also stops cheating.

## Suggested order of work

1. Get the current game running locally and deployed to a free host at a public URL, unchanged (solo, daily and drinking game work without a server).
2. Add a real-time server and replace the `room` code with it: create/join by code first, then random matchmaking.
3. Add accounts (email or Google sign-in) and a database for ratings, history and daily results.
4. Add leaderboards: global, and per university (the long-term idea is a "university galaxy war" where wins claim territory for your uni).
5. Grow the question bank, with a way to add questions without editing code, and check every new question's answer.

## Ground rules

- Every question's answer must be correct. When adding generated content, write a script that verifies it, as was done for maths and word grids.
- Keep the game simple to understand. The owner has repeatedly asked for less complexity, not more.
- Test on a phone-sized screen: most players will be on mobile.
